[Filtering Rules - Precision Extraction Mode]

✅ Characters that must be extracted:
  - Characters listed in screenplay character lines
  - Characters with dialogue and plot interaction
  - Core roles across the main storyline
  - Supporting roles that materially push the plot
  - Characters that must physically appear on screen

❌ Characters that must not be extracted:
  - Nameless faceless passersby (e.g., someone in the crowd)
  - Mentioned-only characters who never appear
  - Background figures with no dialogue and no interaction
  - Abstract entities in poetic description (e.g., fate, embodiment of death)

📋 Decision standard:
  Ask yourself: does this role require a visual design image and an actual on-screen appearance?
  If no, do not extract.

[Character Introduction Rules ⭐ Important]

Each character must include an introduction field to help downstream AI identify roles correctly. It must include:

1. Narrative perspective mapping:
  - For first-person narratives, explicitly state that I maps to this character

2. Identity positioning:
  - Describe the character's narrative identity (protagonist/supporting/antagonist, etc.)

3. Relationships:
  - Relationship with other major roles

4. Address mapping:
  - Common ways other roles address this character

Example introduction:
The protagonist, narrated in first person as I, real name Lin Mo. Husband of Su Qing and son-in-law of Zhang San. Addressed by Su Qing as husband and Mo-ge, and by subordinates as President Lin.

[Character Importance Level Rules]

⚠️ Important: judge by narrative presence and story status, not by glamorous appearance.

S level (absolute lead):
  - Core viewpoint role around whom the story unfolds
  - I in first-person stories is usually S level

A level (core supporting):
  - Major role with substantial interaction with lead
  - Second male/female lead, major antagonist, etc.

B level (important supporting):
  - Appears multiple times, named, advances side plot

C level (minor role):
  - Appears occasionally, limited screen time, but has clear visual identity

D level (bit part):
  - Small role with brief appearance requirement

For S and A roles, design one instantly recognizable visual marker:

Accessory marker: heirloom ring, never-removed necklace, cane.

[Sub-appearance Selection Rules ⭐ Important]

Analyze whether a role has multiple visual forms and output them into expected_appearances.

✅ Record as sub-appearance when visually persistent:
  - Outfit changes: formal/casual/armor switch
  - Age-state changes: younger/older flashback versions
  - Special look states: post-bath towel look, disguise look
  - Lasting hairstyle changes: cut/braid/updo/loose hair

❌ Do not record non-visual or temporary states:
  - Emotion/mental states
  - Health states unless with stable visible markers (e.g., bandages)
  - Temporary action poses
  - Abstract wording like shadow covered, gaze changed
  - Temporary VFX/light states (glow, aura, fire, halo)
  - Skill-casting states
  - One-shot instant states (knocked back, fell down)

⚠️ Decision standards:
  - If the state cannot be represented by visual redesign, do not record
  - If represented mainly by post effects, do not record
  - If it lasts only seconds instead of scene-level continuity, do not record
  - Record only persistent visual changes that require a new character image

📋 expected_appearances format:
  - Every character must have at least id=1 as initial appearance
  - If outfit/age/other persistent changes exist, add id=2,3...
  - change_reason should be brief (e.g., post-bath state, combat outfit, elderly flashback)
